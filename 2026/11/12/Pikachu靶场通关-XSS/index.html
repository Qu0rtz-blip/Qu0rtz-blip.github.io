皮卡丘（Pikachu）XSS 跨站脚本攻击通关记录

实验环境：Windows 10 + Pikachu + Edge
靶场地址：http://10.33.20.10/pikachu/

本次记录皮卡丘靶场 XSS 模块全部 10 个小关卡的通关过程。
XSS 的本质是用户输入被浏览器当成了代码执行：同样是往一个框里贴 payload，有的贴在 HTML 正文里、有的贴在标签属性里、有的贴在 JS 字符串里、有的贴在 href 里——输出位置不同，闭合和触发的方式就完全不同。
打完全部关卡之后回到源码，分析每个漏洞是怎么写出来的，以及正确的修法是什么。

一、XSS 跨站脚本攻击

跨站脚本攻击（Cross-Site Scripting）的根本原因是：用户可控的输入被未经编码地输出到了页面里，浏览器分不清哪部分是页面自己的代码、哪部分是用户的输入，于是把输入当脚本执行了。

按 payload 的投递方式，XSS 分三类：

类型 脚本存在哪里 是否经过后端 触发方式
反射型 只存在于本次请求/响应中 是 一次性，需诱导点击构造好的链接
存储型 存入数据库，持久化 是 每个访问该页面的人都会触发
DOM 型 只在前端 JS 里流转 否 前端把输入写进 DOM，抓包看不到

2.8 xss 之 htmlspecialchars

这个也能从我们的输入看出来，我们输入里有两个单引号 ‘ ，而转义后的内容原样保留了单引号，说明单引号不在htmlspecialchars()函数的管辖范围。这个和htmlspecialchars()函数的flags参数有关，单引号不参与转义，说明该函数使用的级别是ENT_COMPAT。这里不做详细的介绍了，感兴趣的可以看这里[PHP htmlspecialchars函数](PHP htmlspecialchars() 函数 | 菜鸟教程)。

3.1 反射型：输入直接拼进 HTML 输出

3.2 存储型：入库转义防的是 SQL 注入，输出没做 HTML 编码

入库时：

escape() 只做 SQL 层面的转义，防 SQL 注入；但是，escape()通常不会把HTML标签的<和>进行转义；于是读取输出时：

输出到 HTML 时没有任何编码，存进去什么就原样执行什么。防 SQL 注入和防 XSS 是两件独立的事，做了其中一件不等于做了另一件。

3.3 DOM 型：前端 innerHTML 直接拼接

xss_dom.php 中：

innerHTML 把用户输入当 HTML 解析，输入 ' 闭合 href、> 闭合 a 标签，就能注入任意标签与事件。整个过程不经过后端，抓包看不到任何异常流量。

xss_dom_x.php 唯一的区别是输入来源换成了 URL：

payload 从 location.search 解出、URL 解码后同样进 innerHTML——于是攻击者可以构造带 payload 的链接直接投递。

3.4 盲打：两头都没编码

xss_blind.php前端提交入库时与存储型一致（escape 转 SQL、不转 HTML）；管理员后台 admin.php 渲染留言时：

content、name 原样输出，payload 在管理员浏览器里执行。盲打漏洞 = 前端存的时候不管 + 后台取的时候也不管，两头都放行。

3.5 过滤与特殊输出上下文

xss_01 的过滤正则：

  • 没有 i 标志：区分大小写，<ScRiPt> 直接穿透；
  • 特征序列 <script 可回避：<img src=x onerror=...>、<svg/onload=...> 根本不含这个序列。

另注意它是贪婪匹配（(.*) 尽可能多吃），那么嵌套 payload <scr<script>ipt> 实测会被整体替换为空（末尾小写 </script> 也在匹配范围内），并不能绕过。

xss_02 / xss_03 / xss_04：编码了，但没对准输出上下文：

关卡 关键代码 根因
xss_02 htmlspecialchars($_GET['message']) 后输出进单引号 href 默认不转义单引号，可闭合属性
xss_03 htmlspecialchars(...,ENT_QUOTES) 后输出进 href 引号全被转义，但 href 支持 javascript: 伪协议
xss_04 $jsvar=$_GET['message']; 拼进 JS 字符串 HTML 编码在 JS 语境无效，可用 ' 闭合字符串

3.6 成因归纳

XSS 不是没过滤干净，而是输出上下文与编码方式不匹配的一类病。同样的输入，落在正文里要编码标签、落在属性里要编码引号、落在 href 里要限制协议、落在 JS 里要做 JS 转义，用错了一种，其余全部归零。

四、修复方案

XSS 的核心防线是输出编码：把用户数据输出到 HTML 正文、标签属性、JS 字符串等不同上下文时，分别做对应的编码转义（如 htmlspecialchars、JS 转义、JSON 编码），富文本内容则用白名单净化库处理。在此之上再辅以纵深防御：Cookie 加 HttpOnly、部署 CSP 限制脚本来源、输入侧做长度与格式校验、敏感操作加 CSRF token 与二次确认。
