一、XXE

1.1 什么是 XXE

XXE（XML External Entity Injection，XML 外部实体注入）：服务端接收并解析用户提交的 XML，且解析时允许加载外部实体，攻击者就可以在 XML 里声明一个指向本地文件或内网地址的实体，解析器会替攻击者把内容读出来、带回响应——本质上是把”读文件 / 发请求”这个动作外包给了服务器。

要理解它，得先知道 XML 里”实体”是什么。XML 的 DTD（文档类型定义）部分可以声明实体，实体在正文里用 &名字; 引用，解析时会被替换成实体内容：

上面声明的叫内部实体（内容写死在文档里）。外部实体则是把 SYSTEM 关键字后面换成资源的地址：

解析器加载这段 XML 时，会真的去读 file:///etc/passwd，把文件内容替换进 &f; 出现的位置。除了 file://，http://、ftp://、php://filter 等协议都可能被支持——读文件、探测内网端口、（配合 php://filter 读源码）都不在话下。

1.2 为什么这个漏洞越来越少见

XML 本身没毛病，问题在解析器的默认配置。以 PHP 为例，底层用 libxml 解析 XML，libxml ≥ 2.9.0 起默认禁止加载外部实体——现在很多语言默认配置直接堵死了这条路。皮卡丘为了模拟漏洞，在调用解析函数时手动传了 LIBXML_NOENT 选项把外部实体解析重新打开，这个细节在源码分析里再说。

代码分析：

  • **LIBXML_NOENT 是全篇唯一的”开关”**：libxml ≥ 2.9.0 默认禁外部实体，但 simplexml_load_string() 第三个参数传了 LIBXML_NOENT，等于手动把外部实体解析重新打开。
  • 第二环是 echo "<pre>{$data}</pre>"：解析结果（会被实体替换过的内容）原样输出，没有过滤。有回显是这一关打得这么顺的原因——真实场景里很多 XXE 没有任何回显，只能靠外带（OOB）：声明一个 http://攻击者服务器/xx?data=... 的实体，让服务器主动把读到的内容发出来，或者用参数实体嵌套绕过限制，那是另一套玩法；
  • @ 压制解析报错，失败分支只回显固定文案——和反序列化关一样，攻击者拿不到报错细节，但也说明作者没做任何输入校验；

当解析器去读取 /etc/passwd，并把读到的文件内容，直接替换到了根节点<foo>的位置。此时，XML 变成了 <foo>root:x:0:0...</foo>。

四、修复方案

XXE 的修复原则只有一条：解析用户提交的 XML 时，绝不允许加载外部实体。最直接的办法是升级依赖——libxml ≥ 2.9.0 默认就禁了外部实体，只要不手动传 LIBXML_NOENT 这类开关，漏洞天然不存在；更彻底的做法是连 DTD 一起禁（PHP 8 已废弃 libxml_disable_entity_loader()，改用自定义 XML 实体解析器或加 LIBXML_DTDLOAD 白名单式控制），DTD 在绝大多数业务接口里根本用不到。再往上，业务上能用 JSON 就别收 XML（省掉一类解析风险）、对确实需要 XML 的接口做 schema 校验并禁用 file:///php:// 等协议、解析结果输出到页面时同样要做 HTML 转义、WAF 拦 <!DOCTYPE 和 <!ENTITY 关键字，都算加固。
