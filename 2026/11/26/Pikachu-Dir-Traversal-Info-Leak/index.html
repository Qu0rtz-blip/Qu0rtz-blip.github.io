皮卡丘（Pikachu）目录遍历与敏感信息泄露通关记录

实验环境：Windows 10 + Pikachu + Burp Suite
靶场地址：http://127.0.0.1/pikachu/

本次记录皮卡丘靶场 Directory Traversal（目录遍历）与 Sensitive Information Leak（敏感信息泄露）两个模块的通关过程。
这两个漏洞危害等级都不高，但性质不同：前者是”路径可控”，后者是”不该露的东西露了”；
前者要构造 payload，后者往往只需要多看一眼——一个看的是手法，一个看的是意识。

一、目录遍历与敏感信息泄露

1.1 目录遍历（Directory Traversal）

Web 开发里为了让功能灵活，经常把”要操作的文件”定义成变量，由前端传进来：?title=jarheads.php。后台拿到这个值后拼进路径去 require/read。如果不对这个值做校验，攻击者就能用 ../ 往上跳目录，读到设计之外的任何文件。

它和前面打过的文件包含、不安全文件下载是同一个病根——“来自前端的文件名直接进路径”。皮卡丘的概述页专门说明了这一点：三者成因相同，只是出现的位置和现象不同：

1.2 敏感信息泄露（Sensitive Information Leak）

敏感信息泄露不是一个”点”，而是一种结果：不该让前端用户看到的东西，轻易被看到了。常见的有三类，皮卡丘的概述页列得很清楚：

这类漏洞危害常被评为”低”，但它的价值在于给下一步攻击递刀子：一个测试账号能登录后台、一个内网接口能接着打、一个版本号能对上现成的 EXP。所以它单独成关，考点不是技术，是”你有没有多看一眼”。

顺便区分一个容易混的点（皮卡丘概述页特地点了）：不带参数就能列出目录文件（Index of /）算敏感信息泄露，不算目录遍历；带参数、靠 ../ 跳出目录的才叫目录遍历。现象相似，成因不同。

1.3 关卡入口

目录遍历关卡页是两篇小短文（《锅盖头》《楚门的世界》的台词），点击标题会带 title=xxx.php 参数；敏感信息泄露关卡页是一个登录框，”find abc”——找找看哪里漏了。

两个问题：账号直接明文存在 Cookie 里；密码虽然做了 MD5，但 MD5 不带盐、可被彩虹表反查，等价于明文。Cookie 存在客户端，用户随时可改可读——把身份凭证这样交给前端，本身就是一种泄露。

更直接的一条路：abc.php 这个页面根本不校验 Cookie，直接访问 URL 就能看到内容。严格说这属于”未授权访问”，但根子上还是同一个问题——把”该不该给”交给了前端自己判断。

三、源码分析：漏洞是怎么写出来的

3.1 关卡：require 直接拼路径

dir_list.php 的核心代码：

代码分析：

  • require "soup/$filename" 是字符串拼接，$_GET['title'] 里的 ../ 原样进入路径，没有任何过滤、白名单或 basename()；
  • 用 require 而不是 fopen 读文件，意味着被包含的 PHP 会被执行：读 passwd 是文本输出，读同目录的 .php 则是执行——所以它其实同时具备”目录遍历”和”文件包含”两副面孔；

代码分析：

  • 测试账号硬编码在模板注释里——开发期图方便，上线时忘了删。它是”泄露”不是”漏洞”，没有任何代码执行，但直接给出了登录凭证；
  • Cookie 里存了明文用户名和 **MD5(密码)**：MD5 无盐、可反查，明文与哈希在这类场景里安全强度几乎等价；而且 Cookie 在客户端，改起来毫无门槛；
  • abc.php 只根据”有没有 Cookie”来决定显示内容，没有服务端会话校验，直接访问 URL 也能看到页面——身份判断被放在了客户端；
  • 这一关连”防护”都谈不上，它考的是意识：上线前有没有人检查过源码里的注释、Cookie 里的字段、错误页里的路径。

四、修复方案

目录遍历：和文件包含、文件下载同一套思路——不要让用户输入决定文件路径。前端传 ID/枚举值，后端映射到真实文件名；必须传文件名时用 basename() 剥掉路径、拼固定的根目录，再用 realpath() 确认最终路径仍在根目录内，后缀做白名单。顺带，require/include 用于”展示内容”这种只读场景本身就不合适，改用 file_get_contents + 输出转义，至少不会把读到的 PHP 执行掉。

敏感信息泄露：核心是”最小暴露”——HTML 注释、调试信息、测试账号在发布前统一清理（构建流程里加一步检查）；Cookie 只放一个随机 Session ID，服务端存会话状态，不要放账号密码或它们的哈希；错误页统一跳转到自定义页面，关闭 display_errors，不让报错带出版本、路径、SQL；目录列表关闭（Nginx autoindex off、Apache Options -Indexes）；响应头去掉 X-Powered-By、Server 里的版本号。再往上，把”信息泄露”纳入上线检查清单和安全扫描规则，比事后补救有效得多。
